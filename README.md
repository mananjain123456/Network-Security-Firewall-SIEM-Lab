# Network Security & Firewall Monitoring with SIEM Integration

A hands-on network security lab built using OPNsense, Suricata IDS/IPS, and Splunk Enterprise to monitor network traffic, detect suspicious activities, and centralize security logs for investigation.

## 1. Project Overview

This project demonstrates a network security monitoring environment in which OPNsense acts as the primary network firewall, Suricata provides intrusion detection capabilities, and Splunk Enterprise serves as the centralized Security Information and Event Management (SIEM) platform.

The lab integrates network-level monitoring with endpoint log collection to provide visibility into firewall events, intrusion detection alerts, and authentication-related security activities.

Kali Linux is used to generate controlled security testing activity, while Windows and Ubuntu machines provide endpoint security logs.

## 2. Objectives

- Configure OPNsense as a network firewall to monitor and control network traffic.
- Implement Suricata for network intrusion detection.
- Centralize firewall, IDS, and endpoint logs in Splunk Enterprise.
- Investigate suspicious network activity and authentication failures.
- Practice security event analysis using Splunk Search Processing Language (SPL).
- Understand the workflow of a basic Security Operations Center (SOC).

## 5. Implementation

### A. OPNsense Firewall Configuration

- Deployed OPNsense as the primary network firewall.
- Configured network interfaces and firewall rules.
- Monitored inbound and outbound network traffic.
- Used firewall logs to investigate permitted and blocked connections.

### B. Suricata IDS/IPS Integration

- Integrated Suricata with the OPNsense environment.
- Configured network traffic inspection and intrusion detection.
- Monitored security alerts generated by Suricata.
- Investigated suspicious traffic using alert details such as source IP, destination IP, and alert signatures.

### C. Splunk SIEM Deployment

- Deployed Splunk Enterprise on an AWS EC2 instance.
- Configured centralized log collection from Linux and Windows endpoints.
- Organized collected security events using dedicated Splunk indexes.
- Used SPL searches to investigate authentication failures and suspicious activities.

### D. Security Testing with Kali Linux

- Generated controlled security testing activity from Kali Linux.
- Simulated repeated failed authentication attempts.
- Examined the resulting security events in the available log sources.
- Investigated corresponding events through Splunk searches.

## 6. Security Monitoring and SPL Queries

The following are example SPL queries for investigating events. Adjust index names and field names according to your actual Splunk configuration.

**1. Investigating Failed Authentication Attempts**

```spl
index=* "Failed password"
| stats count by host, source
| sort -count
```

**2. Identifying Repeated Authentication Failures**

```spl
index=* "Failed password"
| stats count as failure_count by host, source
| where failure_count > 5
| sort -failure_count
```

**3. Investigating Suricata Alerts**

```spl
index=* sourcetype=*suricata*
| stats count by src_ip, dest_ip, alert.signature
| sort -count
```

**4. Investigating Firewall Events**

```spl
index=* (sourcetype=*firewall* OR sourcetype=*syslog*)
| stats count by host, source
| sort -count
```
